# GOAI 2026 无界应用（Boundless Agents）比赛简介

本文提炼自 GOAI 2026 世界人工智能开源大赛《无界应用｜Boundless Agents 参赛手册》，用于快速理解赛道定位、作品要求、赛事流程和评审标准，不替代组委会正式规则与后续通知。

资料基线：2026-07-28。

## 1. 赛道定位

“无界应用｜Boundless Agents”是 GOAI 2026 的第二赛道，定位为面向真实行业场景的 AI Agent 应用创新。

赛道聚焦个人终端、汽车出行、金融服务、教育和工业制造等高频场景，鼓励参赛团队构建具备以下能力的智能体应用：

- 任务理解与任务拆解。
- 流程编排与多轮交互。
- 工具、API、数据库或业务系统调用。
- 行业知识库与检索增强。
- 上下文、记忆与状态管理。
- 图片、语音、视频或传感器等多模态交互。
- 结构化结果交付、效果验证与运行追溯。

赛道希望作品面向真实用户、真实业务流程和真实任务闭环，形成可运行、可演示、可复制并具有持续使用价值的应用雏形。不鼓励提交以下类型的作品：

- 泛聊天机器人。
- 单点或单轮问答工具。
- 简单内容生成器或 Prompt 演示。
- 缺少用户流程与验证材料的概念展示。

## 2. 参赛对象与组队规则

比赛面向全球个人开发者、开源项目团队、高校学生、科研团队、企业 AI 技术团队、AI 创业团队、产品团队和开发者社区开放。

- 可以个人参赛。
- 组队参赛时，团队人数不超过 3 人。
- 初赛队伍提交后不得变更成员信息。
- 进入复赛后，所有成员需要接受实名信息核验。
- 进入总决赛的团队原则上需要参加 9 月 22 日至 23 日在杭州举行的线下活动。

## 3. 五个行业方向

参赛团队原则上应选择一个行业方向，也可以基于真实需求提出更细分的场景，但需要说明它与对应行业赛题的关系。

| 方向 | 定位 | 重点验证 | 主要安全边界 |
| --- | --- | --- | --- |
| AI+眼镜 | 下一代个人智能终端原生智能体 | 第一视角、语音交互、实时感知、随身陪伴、轻量反馈 | 重视录音录像授权、环境识别边界和个人数据保护，不能只是手机或网页应用的简单复刻 |
| AI+汽车 | 面向车主全生命周期的智能用车 Agent | 购车、用车、养车、售后、出行与座舱体验闭环 | 不直接接入高风险车辆控制，不替代自动驾驶决策 |
| AI+金融 | 面向企业经营与风险研判的金融服务 Agent | 资料理解、规则匹配、风险提示、投研整理和流程辅助 | 不提供确定性投资建议，不替代授信、赔付、风控或合规决策 |
| AI+教育 | 面向个性化学习与教学辅助的教育 Agent | 个性化学习、作业辅导、学情诊断、教师备课和学习陪伴 | 不替代教师或学校评价，涉及学生数据时应使用公开、模拟或经授权脱敏的数据 |
| AI+工业制造 | 面向设备运维与供应链协同的工业 Agent | 设备、质量、工单、库存、排产和供应链协同 | 不直接控制真实生产设备，不替代现场安全生产决策和专业人员判断 |

AI+工业制造方向的参考选题包括设备故障诊断、质量异常分析、工单调度、供应链风险预警和生产计划辅助。

## 4. 核心作品要求

参赛作品至少需要完成一个可演示、可验证的完整任务闭环，并说明以下内容：

- 目标用户、真实需求和场景痛点。
- 用户如何进入、推进和完成任务。
- Agent 架构、模型、工具接口和知识库。
- 数据来源、授权状态、处理方式和适用边界。
- 部署方式、运行入口和第三方依赖。
- 失败处理、风险提示和人工确认机制。
- 结果验证方式与运行证据。
- 开放、复用和后续迭代计划。

官方定义的 Agent 应用闭环为：

```text
任务输入
  → 意图理解
  → 任务规划
  → 模型、知识库、工具或外部系统调用
  → 可理解、可操作、可追溯的结果交付
  → 评测、日志或用户确认
  → 高风险动作的安全限制与人工确认
```

Demo 不应只有理想路径，还应展示信息不足、调用失败、不确定结果或高风险判断等异常分支及其处理方式。

### 5.1 初赛材料

初赛重点评估项目方向、场景价值、产品方案、技术路线、开放或复用价值及可行性。

| 材料 | 是否必交 | 核心要求 |
| --- | --- | --- |
| 作品简介 | 是 | 500 字以内，说明项目名称、赛题、用户、问题、方案、创新点、开放或复用价值及当前进展 |
| 方案 PPT/PDF | 是 | 说明场景来源、用户痛点、产品流程、Agent 能力、模型与工具、数据、合规边界和落地计划 |
| Demo 视频或原型 | 否 | 展示关键交互、样例输入输出和预期效果 |
| 可执行代码包 | 否 | 如提交，应包含运行入口、依赖、配置、样例输入输出和运行证据 |

### 5.2 复赛材料

复赛重点评估 Demo 可运行性、用户流程闭环、技术实现、评测结果、数据合规及开放复用规范。以下材料均为必交：

- 更新版项目方案。
- 可运行 Demo 或 Demo 视频。
- 代码仓库或等价工程材料。
- 数据来源与合规说明。

工程材料需要包含运行入口、依赖说明、配置文件、示例数据、部署说明、测试方法和运行证据。Demo 至少应展示一个从用户输入到结果验证的完整链路，并包含异常处理。

### 5.3 决赛材料

- 决赛路演 PPT。
- 可现场演示、在线体验或本地部署的 Demo。
- 项目一页纸与答辩材料。
- 评审可访问的最终代码仓库或交付包。
- README、部署说明、示例配置、测试方法和必要的演示账号说明。

## 6. 技术与可复现要求

比赛不强制使用指定模型、Agent 框架或工具平台。允许使用商业 API、闭源模型、第三方 Agent 框架和已有项目，但需要完整披露其来源、使用范围及依赖边界。

作品材料至少需要说明：

- 模型选择及其承担的任务。
- Agent 如何规划任务、调用工具和管理状态。
- API、SDK、插件、数据库、业务系统或硬件的权限范围。
- 知识库的构建方式、检索策略、依据引用、更新机制和错误处理。
- 多轮或长任务中的上下文、记忆、状态和历史管理方式。
- 外部能力调用失败后的处理方法。
- 输出依据、日志、截图、评测指标或用户反馈。

复赛起必须提供运行入口、依赖安装、配置方法、环境要求和复现说明。Demo 应满足以下验证条件：

- 能够从零开始运行。
- 至少完成一个完整任务链路。
- 样例数据、权限和适用边界清楚。
- 失败与异常分支可以解释。
- 输出结果有依据或运行证据可追溯。
- PPT、视频、仓库、文档和现场展示相互一致。

## 7. 开源、数据与安全要求

比赛鼓励开放代码、文档、工具组件、示例数据、应用模板和运行报告，但不强制所有作品完整公开开源。

- 初赛不强制提交代码，但需要说明开放或复用计划。
- 复赛和决赛需要提供评审可访问的代码或等价工程材料。
- 使用商业 API 时，需要披露调用环节、费用假设、权限范围、可替代性和潜在锁定风险。
- 使用闭源模型时，需要说明使用范围、选择原因、替代方案、迁移成本和对可复现性的影响。
- 基于已有项目开发时，需要说明原项目来源、团队新增贡献、创新点及协议兼容性。
- 第三方模型、代码、数据集、工具和素材必须遵守相应许可证，并披露关键版本。
- 使用真实数据时必须具备合法授权，并完成必要的脱敏和隐私保护；使用模拟数据时需要说明模拟逻辑、字段含义和适用范围。
- 对模型幻觉、数据缺失、接口异常、不确定结果和高风险建议，应提供依据来源、置信度说明、风险提示或人工确认机制。

任何作品均不得以 Agent 输出替代专业机构、教师、金融机构、现场安全人员或其他责任主体的最终判断。

## 8. 评审标准

| 评审维度 | 权重 | 重点关注 |
| --- | ---: | --- |
| 行业场景价值 | 25% | 问题是否真实、明确且有代表性，价值收益是否清晰，是否具有复制和推广潜力 |
| Agent 能力与任务闭环 | 25% | 是否具备任务理解、多轮交互、计划、工具调用、知识增强、记忆和结果验证能力 |
| 产品体验与 Demo 完成度 | 20% | 交互和流程是否清楚，反馈是否及时，Demo 是否稳定且容易验证 |
| 技术实现深度 | 15% | 架构是否清晰，模型、工具、知识库、多模态和工作流是否合理，工程是否可复现 |
| 安全、合规与可追溯 | 10% | 数据来源、风险边界、人工确认、依据和追溯机制是否完整 |
| 开放或复用贡献 | 5% | 是否提供可复用模板、组件、示例数据、文档和清晰的开源计划 |

各行业还有个性化关注点：

- AI+眼镜：眼镜原生性、第一视角交互和轻量反馈。
- AI+汽车：用车生命周期、服务链路和车辆安全边界。
- AI+金融：依据追溯、风险提示、合规和避免越权决策。
- AI+教育：场景真实性、个性化、教学友好性和学习数据合规。
- AI+工业制造：多源信息融合、流程闭环、解释性、可操作性和安全生产边界。

## 10. 红线与严重扣分项

以下情形可能导致严重扣分、取消成绩或取消参赛资格：

- 只有概念、PPT 或营销材料，无法提供 PoC、实验、仿真、日志、视频或等价验证证据。
- 评审无法根据 README 和部署说明复现核心 Demo。
- 决赛展示与复赛承诺严重不符，或未披露已有项目基础。
- 抄袭、套壳、伪造结果或购买虚假 Star、Fork、Issue、PR。
- 隐瞒数据来源、许可证、商业 API、闭源模型、个人信息、企业数据或现场控制边界。
- 未经允许私下共享代码，导致不同团队提交的代码雷同。
- 侵犯第三方知识产权、隐私权、商业秘密或数据授权边界。
- 在金融、教育、工业、汽车或个人终端等高风险场景中越权替代专业人员或机构决策。
