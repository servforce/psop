# PSOP GOAI 2026 Demo 视频脚本

## 1. 成片设定

| 项目 | 设定 |
| --- | --- |
| 成片时长 | 目标 114 秒，最终不得超过 120 秒 |
| Demo 场景 | 操作员佩戴 Rokid 眼镜，在 PSOP 引导下完成机械臂组装 |
| 画面规格 | 16:9，1920×1080，建议 30 fps，中文字幕 |
| 叙事主线 | 传统经验载体 → 构建与验证 Skill → Rokid 现场执行 → Replay 与持续改进 |
| 核心表达 | PSOP 将现场经验转化为可执行、可验证、可回放、可审计的现实世界 Skill |
| 核心理念 | 在确定性的执行骨架上，生长出柔性的智能 |

本脚本中的终端提示文字是拍摄目标文案。最终成片应使用真实 Skill、真实 Run 和真实终端输出；如实际措辞不同，应保留真实输出，不使用后期特效伪造产品能力。加载等待可以加速，但必须标注倍速。

开场动画的完整生成参数与旁白要求见 [14 秒 AI 3D 开场提示词](demo-video-ai-opening-prompt.md)。

## 3. 旁白录音稿

以下文字可直接交给配音人员。Rokid 第一视角异常处理段应以现场音和真实终端反馈为主，不要用旁白盖住交互。

> 四足机器人维修遇阻。工程师翻手册、问服务群、远程连线专家，信息分散，沟通反复。PSOP，让经验成为现场指引。
>
> 导入视频、文档和标准，Builder 智能体生成任务步骤、证据要求、安全约束和异常恢复路径。
>
> Skill 发布后编译为 PSOP-EG，并用正例、反例和边界场景进行多模态黑盒时序测试。
>
> 通过测试的 Skill，开始在 Rokid 眼镜上运行。
>
> 操作员无需离手查文档，指引始终在第一视角中。
>
> 每次提示、现场输入、智能判断与证据，都沉淀为可追溯的运行事实和 Replay。
>
> 从经验到 Skill，从指导到验证，再从现场反馈持续改进。PSOP，让现实作业可复制、可监管、可沉淀。

## 4. Rokid 第一视角拍摄设计

### 4.1 必须拍到的真实交互

1. 眼镜终端显示当前任务和步骤进度。
2. 进入作业前的断电确认或等价安全检查。
3. 至少一条可直接执行的步骤指引，而不是只有步骤标题。
4. 操作员通过真实终端能力提交文字、语音或当前视野证据。
5. 一次未通过判断及明确的纠正指引。
6. 纠正后证据通过，Run 最终完成。

推荐保留 `01:02–01:16` 为相对连续镜头，以证明异常识别和反馈来自真实运行。若模型或网络等待超过 2 秒，可以剪短等待，但异常提交、系统反馈和纠正动作三者的前后顺序必须完整。

### 4.2 眼镜屏幕文案原则

- 每屏只表达一个动作，优先使用“对象 + 动作 + 完成条件”。
- 单屏正文不超过两行，关键指引尽量控制在 24 个汉字以内。
- 危险或禁止动作必须直接写出，例如“请勿锁紧”，不要只显示“校验失败”。
- 进度、当前动作和判断结果分别稳定显示至少 2–3 秒。
- 终端提示使用 Rokid 原生绿色文字；后期中文字幕放在画面底部，不得遮挡眼镜屏幕内容。

建议在正式拍摄前，将以下目标语义写入机械臂 Skill 并完成一次预演：

```text
机械臂组装｜步骤 1/5
确认设备断电，并清点底座、立柱和螺钉

机械臂组装｜步骤 2/5
将立柱定位孔对齐底座，暂勿锁紧

定位孔未对齐，请勿锁紧
重新对齐后再提交当前视野

对齐正确，可继续紧固
证据通过｜任务完成
```

具体措辞以真实 Runner 输出为准，不要求逐字一致。

### 4.3 画面可读性

- 避免让绿色文字长期落在白墙、灯具或高亮反光区域；工作台优先使用深灰、木色等中性背景。
- 拍摄前导出 10 秒测试片，在普通笔记本屏幕上确认绿色文字无需暂停即可读清。
- 固定工作台、零件盒和工具位置，操作动作保持在第一视角中央区域。
- 确认 Rokid 录制文件的方向和分辨率。若源文件为竖屏，在 16:9 成片中采用完整竖屏画面加暗色背景，不要强行裁掉终端文字。
- 第一视角快速转头容易眩晕；移动视线时放慢速度，每次提示出现后保持头部稳定。

## 5. 素材清单与推荐拍摄顺序

### 5.1 必备素材

- 四足机器人维修、维修手册、微信服务群与专家连线的 AI 3D 开场镜头。
- PSOP Builder 构建 Skill 的 16:9 屏幕录制。
- 发布编译、PSOP-EG 和黑盒时序测试结果录屏。
- 操作员佩戴 Rokid 的第三人称正面或侧面镜头。
- Rokid 第一视角完整 Run 原片，建议至少保留两条可用 Take。
- 机械臂组装前、异常状态、纠正状态和最终完成状态特写。
- Web 端 Replay 完整时间线录屏。
- PSOP Logo、仓库地址或二维码、Apache-2.0 标识。

### 5.2 推荐顺序

1. 先完成 Skill、测试场景和真实 Run 预演，锁定终端输出。
2. 录制 Web 端构建、编译、测试和 Replay 画面。
3. 固定工作台与零件位置，录制一条完整 Rokid Run 作为事实母版。
4. 再录一条 Rokid 备用 Take，并补拍第三人称操作镜头。
5. 最后拍痛点素材、机械臂完成特写和结尾 Logo 镜头。

## 6. 剪辑与验收要求

- 开场 10 秒内必须让评委看到工业现场问题，14 秒内必须知道 PSOP 是什么。
- Rokid 第一视角总占比建议不少于 35 秒，其中至少 12 秒为相对连续真实交互。
- 浏览器录屏只放大评委需要看的关键词，避免展示密钥、内网地址、个人信息和冗长 ID。
- 任何加速、跳步或中间步骤省略都使用 `2×`、`中间步骤节选` 等明确标识。
- 异常反馈必须来自真实 Run；不要通过后期添加不存在的终端提示。
- 全片配中文字幕，旁白清晰高于背景音乐；第一视角段适当降低音乐，保留操作和确认声音。
- 结尾不要只停留在“完成组装”，必须回到“经验可复制、过程可监管、知识可沉淀”的行业价值。
- 导出后检查总时长 `≤120 秒`，并分别在手机和电脑上检查终端绿色文字与字幕可读性。

最终成片应让评委在两分钟内确认四件事：PSOP 解决的是真实工业问题；Skill 经过构建、编译和测试；Rokid 能在第一视角中自然协助现场执行；整个过程留下可验证、可回放的事实。
